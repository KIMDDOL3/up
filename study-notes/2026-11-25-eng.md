# 오늘의 미션 (수요일 읽기 — '통번역 대신 뼈대 먼저' 훈련)

- 오늘의 포인트: **영어 문장이 길게 느껴지는 진짜 이유는 단어가 많아서가 아니라, 주어와 동사 사이에 수식어가 끼어 있기 때문이다.** 읽기 챕터는 막힌 문장을 여섯 층으로 분류하는데, 그중 가장 자주 나오는 층이 '구조'층 — 단어는 다 아는데 누가 누구를 수식하는지, 조건이 어디 붙는지 몰라서 멈추는 경우다. 해법은 완벽한 통번역이 아니라 뼈대 먼저 잡기: 주어+동사를 먼저 소리 내어 찾고("The client wants..."), 나머지는 조건(if~)·수식어(that~)로 태그만 붙인다. 뼈대가 잡히면 문장의 '약속'이 보인다 — 조건문은 "~라면 ~한다", 관계절은 "그 ~가 어떤"으로 대화에서도 그대로 쓰인다. 그래서 오늘은 이메일·공지·앱 알림 같은 실제 문장에서 뼈대를 잡고, 그 문장을 통째로 입에 익히는 훈련을 한다. 읽기와 말하기가 같은 문장에서 만나는 지점이다.
  - 인용: 4-reading.md 「单词认识，却不知道谁修饰谁、条件落在哪」 (단어는 아는데, 누가 누구를 수식하는지·조건이 어디에 떨어지는지 모른다.)
  - 인용 2: 「遇到长句，先找主语、核心动词、条件与转折」 (긴 문장을 만나면 먼저 주어·핵심 동사·조건·전환을 찾아라.)
  - 왜 이런 규칙인가: 초중급 눈은 긴 문장을 앞에서부터 단어 단위로 통번역하려 한다. 그런데 영어는 핵심(주어+동사)이 앞에 나오고 수식어가 뒤에 붙는 언어라, 번역하려는 순간 앞부분만 반복해서 읽게 된다. 뼈대를 먼저 잡으면 "무엇이 무엇을 한다"가 한 번에 확정되고, 나머지는 세부사항으로 뒤에서 붙는다. 이건 읽기 속도 문제가 아니라 머릿속 문장 처리 순서 문제라서, 소리 내어 말하기로 같은 구조를 입에 익히면 회화에서도 긴 문장이 튀어나온다.
  - 흔한 실수: 틀린 문장 — "The client which we met last week wants the report." → 고친 문장 — "The client that we met last week wants the report." (사람/조직인 client에는 that/who가 자연스럽고 which는 사물에 쓴다. 관계절을 통째로 덩어리로 말하려면 that로 통일하는 게 가장 안전하다.)

- 오늘의 표현 5개 (실제 이메일·공지·일상에서 뼈대 잡기 + 통째로 말하기):
  1. "The client **that we met last week** wants the report by Thursday." — 뼈대: The client wants... / 지난주에 만났던 고객이 보고서를 목요일까지 원해. (직장·관계절)
  2. "If the tests pass by Friday, **we can ship the update on Monday.**" — 뼈대: we can ship... / 금요일까지 테스트가 통과되면, 월요일에 업데이트를 배포할 수 있어. (직장·조건문)
  3. "The person **you should contact** about access is Daniel, not the help desk." — 뼈대: The person is Daniel / 접근 권한 관련해서 연락할 사람은 데스크팀이 아니라 다니엘이야. (직장·관계절)
  4. "The café **on the corner that used to be a bookshop** is closing next month." — 뼈대: The café is closing / 모서리에 있던, 원래 서점이던 카페가 다음 달에 문 닫아. (일상·관계절)
  5. "Long story short, the flight was delayed, **so we got home after midnight.**" — 뼈대: the flight was delayed / 간단히 말하면, 비행기가 지연돼서 자정 넘어 집에 도착했어. (일상·요약 표현)

- 미션 (15~20분): **오늘 예문 3개에서 뼈대를 소리 내어 찾고 → 문장 통째로 말하기 → 실제 영어 문장 1개에 적용하기**
  - 절차:
    1. **재료 고르기(4분)**: 오늘 예문 5개 중 실제로 쓸 상황 3개를 고른다(예: 고객 요청, 조건 배포, 카페 소식). 그리고 실제로 받은 영어 이메일·공지·앱 알림 중 긴 문장 1개를 준비한다.
    2. **수행(10분)**: (a) 각 문장에서 주어+동사만 먼저 소리 내어 말한다("The client wants", "we can ship"). (b) 이어서 수식어·조건을 붙여 전체 문장을 3회씩 소리 내어 말하며 녹음. (c) 준비한 실제 문장에서 주어+동사를 찾고, 나머지를 조건/수식어로 분류한다.
    3. **확인(6분)**: 녹음을 다시 들며 체크 — 뼈대가 먼저 또렷하게 들리는가, 관계절이 that 덩어리로 자연스럽게 이어지는가. 실제 문장의 뼈대 1줄을 적어 둔다.
  - 소요: 15~20분
  - 완료 조건: 이 노트 `## 기록`에 말한 문장 1개 + 실제 문장의 뼈대 1줄 기록

## 미니 퀴즈 (11-25 읽기)

1. "The report that we submitted last Friday was rejected."에서 문장의 핵심 뼈대는?
   (a) The report was rejected (b) We submitted last Friday
2. "If the package arrives today, I'll start assembling tonight."을 읽고, 조립을 시작하는 조건은?
   (a) 오늘 도착하면 오늘 밤 시작 (b) 도착과 무관하게 오늘 밤 시작
3. 빈칸: "The café ___ used to be a bookshop is closing next month." (1단어)

## 퀴즈 정답 (11/26 공개용)

1. (a) — 주어 The report + 동사 was rejected가 뼈대다. that we submitted last Friday는 수식어 덩어리일 뿐, 문장의 약속은 "보고서가 반려됐다"이다.
2. (a) — If절이 조건, I'll start가 결과다. 조건문 뼈대를 먼저 잡으면 "도착 → 시작" 순서가 바로 보인다.
3. that — 사물이지만 사람 취급 조합이 아니므로 that이 가장 안전하고 자연스럽다. which도 문법상 가능하지만 대화에서는 that이 표준이다.

## 어제 되돌아보기 (11-24 듣기)

- 어제 미션: 오늘(11-24) 예문 3개를 연음 덩어리(Didja/wanna/shoulda)로 소리 내어 말하고 녹음 + 30초 영상 구간에서 못 들었던 문장 1개를 자막 사다리로 복원.
- 어제 퀴즈 정답:
  1. (a) Did you get the report? — did you가 연음되면 '디쥬'로 들린다. 딸깍 끊긴 '디드 유'보다 '디쥬'가 원어민 속도의 기본값이다.
  2. (a) should have — shoulda는 조동사 have가 약화된 소리고, should of는 이 소리를 잘못 적은 흔한 오기다.
  3. do — What do you가 약화·연음되어 '워더야'가 된다. 조동사·조사류는 강세를 잃고 줄어드는 게 영어 리듬의 기본이다.
