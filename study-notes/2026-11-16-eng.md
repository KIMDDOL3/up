# 오늘의 미션 (월요일 word-list — Common 단어장 단어를 일상·직장 덩어리로 굴리기)

- 오늘의 포인트: **Common 단어장의 constraint, timeout, overhead, benchmark, pragmatic은 코딩 전용 용어가 아니라 일상·직장에서 자주 쓰이는 고급 표현이다.** "예산이 절대 제약이다"는 "Budget is a **hard constraint**", "API가 시간 초과를 만났다"는 "The API **ran into a timeout**", "매일 요리하는 수고를 줄인다"는 "**cut the overhead**"처럼 한 덩어리로 굴러온다. benchmark는 명사뿐 아니라 동사로 "**benchmark A against B**"(A를 B와 벤치마크하다) 형태가 실무 표준이고, pragmatic은 "the pragmatic choice(현실적으로 제일 나은 선택)"처럼 태도를 묘사한다. 특히 timeout은 "시간 초과"라는 뜻만 외우면 쓸 자리를 못 찾는데, 실제로는 run into / hit / keep timing out 처럼 **동사 조합째로** 저장해야 회의에서 즉석으로 튀어나온다.
  - 인용: 2-vocabulary.md "比如 `delay`、`block`、`risk` 都可以出现在项目更新里，却不是同一件事。" (delay, block, risk는 프로젝트 업데이트에 모두 나올 수 있지만 같은 이야기가 아니다.)
  - 왜 이런 규칙인가: 원어민 머릿속에서 constraint는 "초과하면 안 되는 빨간 선"이라는 상황 그림째로 저장되어 있다. 그래서 예산·시간·인원을 얘기할 때 "budget/time is a hard constraint"가 한 덩어리로 나오고, 뜻만 외운 학습자는 "we cannot go over the budget because it is a limit we must respect"처럼 길게 풀다가 멈춘다. 덩어리째 외우면 말하는 속도와 정확도가 같이 올라가고, 들을 때도 회의 템포를 놓치지 않는다.
  - 흔한 실수: 틀린 문장 — "The API made three timeouts today." → 고친 문장 — "The API hit three timeouts today." (timeout은 make와 안 어울린다. hit / run into / kept timing out이 자연스러운 조합이다.)

- 오늘의 표현 5개 (일상·직장에서 실제로 말하는 문장):
  1. "The API keeps **running into a timeout** — can we raise the limit to 30 seconds?" — API가 계속 시간 초과를 만나네. 제한을 30초로 올릴 수 있어? (개발·장애 대응)
  2. "Budget is a **hard constraint** this quarter, so we can't hire anyone new." — 이번 분기는 예산이 절대 제약이라 신규 채용은 못 해. (직장·계획 회의)
  3. "Let's **benchmark** our shipping time **against** last year's numbers before we celebrate." — 자축하기 전에 배송 시간을 작년 수치와 비교해 벤치마크하자. (직장·성과 점검)
  4. "Meal prep on Sunday **cuts the overhead** of cooking every single night." — 일요일에 밀프렙 해두면 매일 밤 요리하는 수고가 줄어. (일상·생활 꿀팁)
  5. "Taking the bus is the **pragmatic choice** when parking costs twenty dollars." — 주차비가 20달러라면 버스 타는 게 현실적인 선택이지. (일상·이동 판단)

- 미션 (15~20분): **다섯 덩어리 중 3개로 '내 이번 주 실제 상황' 문장을 만들어 소리 내어 말하기**
  - 절차:
    1. **재료 고르기(4분)**: 5개 덩어리(running into a timeout / a hard constraint / benchmark A against B / cut the overhead / the pragmatic choice) 중 이번 주에 실제로 쓸 상황 3개를 고른다. 오늘 예문의 주어·세부사항만 내 상황으로 바꾸고, 덩어리 자체는 깨면 실패.
    2. **수행(10분)**: 3문장을 순서대로 이어지는 짧은 시나리오(예: 장애 보고 → 제약 확인 → 대안 선택)로 만들고, 소리 내어 3회씩 말한 뒤 휴대폰에 녹음한다. timeout 문장은 hit / run into 조합이 나오도록 3회 반복.
    3. **확인(5분)**: 녹음을 다시 들으며 체크 — (a) made a timeout / benchmarked to 같은 어색한 조합이 섞였는가, (b) 각 덩어리가 한 호흡에 나왔는가. 버벅인 덩어리 1개를 골라 문장째 3회 반복 녹음.
  - 소요: 15~20분

## 미니 퀴즈 (11-16 word-list)

1. 회의에서 API 장애를 보고할 때 가장 자연스러운 것은?
   (a) The API hit three timeouts today. (b) The API made three timeouts today.
2. "우리 프로세스를 업계 표준과 비교해 보자"를 가장 자연스럽게 말할 때는?
   (a) We should benchmark our process against the industry standard. (b) We should benchmark the industry standard to our process.
3. 빈칸: "Cooking every night is a lot of ___ — Sunday meal prep saves me hours." (힌트: Common 단어장 단어 — 불필요한 부담·수고)

## 퀴즈 정답 (11/17 공개용)

1. (a) — timeout은 hit / run into와 조합된다. made는 어색한 비원어민 콜로케이션.
2. (a) — benchmark A against B가 실무 표준 어순. to를 쓰면 방향이 뒤집힌 어색한 문장이 된다.
3. overhead — "cut the overhead(수고·오버헤드 줄이기)" 덩어리. 기술 단어장 단어가 생활 루틴에 그대로 쓰이는 사례.
